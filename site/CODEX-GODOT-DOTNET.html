Godot/.NET disponível para testes no Codex

Configuração local verificada em 13/10/2026, Windows x64. O Codex executa os scripts PowerShell do projeto e o Godot real pelo terminal local. A validação abaixo usa essa execução direta; não depende de um servidor MCP do Godot.

Configuração realizada

  • Godot: C:\dev\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe.
  • Versão retornada: 4.7.2.stable.mono.official.ed1daf0bf; pasta GodotSharp presente.
  • SDK selecionado por global.json: .NET 8.0.425, alvo net8.0, C# 12.
  • Python selecionado no PATH: 3.11; requisito mínimo 3.10.
  • GODOT_DOTNET gravada no ambiente do usuário, sem mudar o PATH ou a política permanente de execução de scripts.

Tools/Common.ps1 consulta também o ambiente persistente do usuário quando a variável está ausente no processo. Assim, os scripts funcionam no Codex já aberto. Novos processos passam a herdar a variável após reabrir o aplicativo/terminal. A variável antiga GODOT_EXE, apontando para outra instalação, não é usada por estes scripts. -Godot explícito continua tendo precedência.

Para reconfigurar nesta máquina ou em outra instalação, dentro da raiz:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Setup-Codex.ps1 -Godot "C:\dev\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe"

O setup valida versão/edição do engine, GodotSharp, SDK 8 e Python antes de persistir o caminho. Ele utiliza as ferramentas instaladas; não baixa binários. Foi verificada a rejeição da edição 4.7.2 sem .NET, com exit 1, e a resolução do caminho persistente em um PowerShell sem GODOT_DOTNET no processo.

Executar os gates automáticos

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Test.ps1

O comando executa, em ordem: validador do projeto, validador de configuração, 22 testes PowerShell da toolchain, três testes Python de saúde dos logs, 31 CoreTests, build C#, importação Godot, smoke real com servidor dedicado e quatro clientes ENet e gate de concorrência/reconexão/restore headless. Este último usa a porta 27625 e fixtures de teste separadas; o smoke usa -Port. Cada execução guarda logs e report.json em Build/validation/<execução>/; os detalhes do smoke ficam em Build/smoke/<id>/. Falha interrompe a sequência e retorna código diferente de zero. Erros do Godot e avisos de MTU reprovam os gates de rede mesmo quando o processo retorna zero. O gate ENet usa Tools/NetworkAcceptance.tscn; seu recorte e os casos ainda pendentes estão em TESTES-E-LIMITACOES.md.

Acrescente -Presentation para executar Tools/PresentationAcceptance.tscn com renderer real em um desktop disponível. A fixture envia eventos sintéticos de teclado/mouse, captura painéis/ambientes e verifica layout, foco, combate no inventário e câmeras da sala do gerador. Não substitui controle físico nem a matriz manual completa. Use --quit-active após NetworkAcceptance.tscn -- para exercitar saída da árvore com quatro peers ativos, em execução separada (a fixture usa a porta 27625). Exports e ensaio WSL2 são testes separados.

Os relatórios históricos em Docs/ não são sobrescritos. Outputs e dados de usuário não devem ser incluídos em pacotes. O smoke gera perfis/campanhas de teste com IDs únicos, preservando as campanhas normais.

O Codex pode executar esse comando diretamente. Para um atalho opcional na barra do app, cadastre o mesmo comando como ação nas configurações de ambiente local, conforme a documentação oficial de ambientes locais. Esse atalho de interface não foi cadastrado nesta execução.

Abrir para a matriz manual

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Launch-Four.ps1

O primeiro abre o menu após build/CoreTests/importação. O segundo abre um servidor e quatro clientes visuais com campanha/perfis de teste separados. Encerre todos os processos desse teste ao terminar. Consulte TESTES-E-LIMITACOES.md para concorrência, reconexão, restore, combate, inventário e aceitação visual.

Validação após corrigir o smoke · 13/10/2026

Execução consolidada aprovada: Build/validation/20261013-105258-c99140f2/report.json. Validadores, 22 testes PowerShell, 26 CoreTests, build e importação passaram. O smoke real de 35s em Build/smoke/55760c6def7f/report.json passou com os quatro clientes, incluindo Wesker em balcony.

O controlador Game/SmokeBotNavigation.cs mantém os pontos da rota entre inputs, evitando as trocas do primeiro ponto que faziam Wesker oscilar perto do spawn. O novo teste reproduz o erro anterior com feedback de snapshots atrasado e passa com a correção. O servidor ainda registra aviso de MTU e erro de envio ao encerrar; matriz manual, concorrência/reconexão/restore real, exportações e desempenho continuam pendentes. Veja TESTES-E-LIMITACOES.md para os limites.
