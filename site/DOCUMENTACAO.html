Manutenção da documentação visual

O README apresenta o jogo; os guias explicam como executar e manter; documentos datados registram evidências de uma implementação. Consultar o inventário documental e o estado dos testes.

Regra obrigatória: atualização de todas as referências

Qualquer alteração que afete documentação, páginas ou apresentação do jogo deve atualizar todas as referências afetadas na mesma entrega, conforme a regra em AGENTS.md. Isso também se aplica quando uma mudança de código, dados, arte, áudio ou versão torna uma descrição, instrução ou captura desatualizada.

  1. Identificar os conceitos, nomes, caminhos e comportamentos alterados. Pesquisar suas ocorrências e dependências no repositório e consultar o inventário documental; a busca literal sozinha não identifica todas as referências.
  2. Atualizar README, guias, portal, HTMLs, galerias e apresentação afetados, incluindo navegação, links, âncoras, exemplos, instalação, controles, versões exibidas, imagens, legendas, créditos e manifestos. Revisar também referências de entrada para arquivos ou seções renomeados, movidos ou removidos.
  3. Alterar a fonte e o gerador correspondente antes de regenerar os derivados. Conferir hashes, origem e contexto quando houver troca de mídia. Preservar registros históricos datados e tags publicadas; marcar conteúdo substituído e indicar a referência atual sem falsificar evidências antigas.
  4. Conferir sincronização de versão, links, âncoras e dependências com os comandos abaixo; revisar o resultado renderizado das páginas e mídias alteradas. Registrar evidências e limitações de validação, inclusive pendências locais que não possam ser verificadas em um clone limpo.

A entrega só está completa quando as referências afetadas estão coerentes com o estado descrito. Alterações exclusivamente documentais continuam sem incremento da versão do jogo.

Gerar o portal

python -m pip install -r Tools/requirements-docs.txt
python -B Tools/release_version.py check
python -B Tools/build_public_galleries.py
python -B Tools/validate_docs.py
python -m mkdocs build --strict
python -m mkdocs serve

Para recapturas locais do painel de configurações, execute a fixture indicada em Controles editáveis e depois python -B Tools/build_public_galleries.py --refresh-settings. O exportador preserva as imagens anteriores em media/history/pre-bindings-2026-10-15/ e atualiza o acervo e hashes; --curate também conserva os registros históricos. As capturas mais recentes vêm de Build/ui-accents-2026-10-15/, usando também --restore-suite --style-suite --accent-suite. --refresh-ui-style publica também inventário/mapa/baú e os destaques do teclado. O estado anterior aos novos estilos fica em media/history/pre-ui-style-2026-10-15/, com originais e hashes. Critérios e resultados. O estado anterior a vínculos verdes/hover vermelho e detalhes do baú fica em media/history/pre-accents-2026-10-15/. Revisão atual. O estado anterior ao botão de restauração fica preservado em media/history/pre-restore-2026-10-15/.

A seleção de itens da lista do baú é recapturada pela fixture com --style-suite --chest-list-suite, em Build/chest-list-details-2026-10-15/. python -B Tools/build_public_galleries.py --refresh-chest-list publica as duas capturas específicas e atualiza a imagem genérica do baú, preservando a anterior em media/history/pre-chest-list-2026-10-15/. Evidências.

O complemento de navegação usa também --chest-navigation-suite, com saída em Build/chest-navigation-2026-10-15/. --refresh-chest-navigation publica três capturas próprias de foco nos painéis/lista vazia, sem substituir as evidências anteriores de clique/retirada. Navegação.

--chest-enter-suite acrescenta transferências por Enter/Enter numérico, Echo, vazios, versões e pausa; saída em Build/chest-enter-2026-10-15/. --refresh-chest-enter publica duas capturas próprias com hashes no manifesto. Transferências.

O site é gerado em Build/docs-site, com busca em português e caminhos próprios para GitHub Pages de projeto. Markdown e mídias versionadas bastam para um clone limpo. A variável PAGES_BASE_URL permite usar o endereço retornado pelo GitHub; o padrão é https://felipestroff.github.io/Operation-Spencer-Docs/.

Coleção pública e acervo local

Os retratos atuais de Jill são recapturados por Tools/JillPortraitPreview.tscn e publicados por python -B Tools/build_public_galleries.py --refresh-jill. Cartão, inventário e baú anteriores ficam em media/history/pre-jill-2026-10-15/, com hashes e contexto preservados. --curate usa as novas fontes. Reprodução e limites.

Docs/media-manifest.json registra fonte, contexto, hashes, direitos e edições. Capturas são cópias binárias do acervo; não há recomposição, alteração da luz ou redimensionamento. source_commit=null significa que o SHA da captura não foi registrado originalmente; o HEAD atual não foi inventado como origem.

Build/ continua ignorada. Somente na máquina que possui o acervo, executar:

python -B Tools/build_public_galleries.py --curate

Esse comando reconstrói a seleção explícita e exporta as galerias existentes de conceitos, portas e lareiras com suas dependências visuais. Os geradores originais continuam em Tools; o exportador não substitui modelagem ou renders. O limite da coleção é 200 MiB. Para atualizar, revisar a seleção no gerador, conferir o conteúdo no navegador e revisar o diff do manifesto.

Para a revisão arquitetônica de 15/10/2026, gerar primeiro os renders de ArchitectureArtAcceptance, ArchitectureUiPreview e InspectionAcceptance --rain-only --rain-output=res://Build/architecture-ps1-2026-10-15/rain, sempre com perfil/campanha de fixture isolados no App. Em seguida executar python -B Tools/build_public_galleries.py --refresh-architecture. O exportador preserva as dez imagens anteriores em Docs/media/history/, atualiza a fonte do acervo, publica 43 pares antes/depois e regrava os hashes. --curate também usa as novas fontes e preserva os registros históricos. Ver reprodução, evidências e limites.

Classificar cada imagem: cena de gameplay/fixture no Godot, inspeção de GLB, interface ou conceito image_gen. Partida manual exige evidência própria. Protótipos não são apresentados como arte implementada. Inspirações externas permanecem como links identificados em fontes.

O catálogo sonoro público expõe metadados e três derivados de gravações CC0 já integrados. Os demais bancos têm links/créditos, sem masters nem áudio embutido. Nunca copiar as galerias locais de áudio indiscriminadamente: algumas contêm Mixkit/Pixabay e comparações históricas em base64. A regra de origem dos novos SFX em AGENTS.md continua obrigatória.

Evidência e histórico

Não substituir testes reais por badges. Cada resultado deve indicar data, SHA-base, condições e limites. Preservar registros antigos e corrigir o estado atual na entrada correspondente, sem reescrever resultados históricos.

Links de evidências locais antigas são identificados como locais; as galerias públicas são uma seleção, não o arquivo completo de logs. Mudanças somente em documentação atualizam o portal, sem incrementar a versão do jogo.

Publicação automática em repositório separado

O portal fica em https://felipestroff.github.io/Operation-Spencer-Docs/ e seu repositório público é Operation-Spencer-Docs. O repositório do jogo permanece privado. docs-publication.json registra o destino. Referências a fontes, commits e Actions do jogo exigem acesso ao repositório privado; esses arquivos não são copiados para o portal.

Depois de cada integração validada na main, o workflow Release and documentation chama Documentation Pages explicitamente, inclusive após commits de versão do bot. O job gera o MkDocs, valida hashes/links e usa Tools/publish_docs.py para copiar somente arquivos estáticos permitidos ao diretório site/ de um checkout separado. Não há clone/mirror do histórico privado, código do jogo, masters, saves ou binários. As fontes web são as fornecidas pelo tema MkDocs, sem fontes do sistema.

Uma deploy key exclusiva do repositório público, com escrita, fica no secret DOCS_PUBLISH_KEY do repositório privado. GITHUB_TOKEN permanece restrito ao próprio repositório; a chave permite enviar o site ao outro destino. O push por SSH aciona o workflow público Deploy public documentation, que publica o Pages. Nenhuma credencial é gravada nos arquivos ou no histórico do portal.

A variável privada PAGES_ENABLED=true habilita a chamada automática. O preparo python -B Tools/github_release_setup.py --apply configura Pages no destino público já criado; não muda a visibilidade do jogo nem o plano da conta. Para repetir apenas a documentação, executar Documentation Pages manualmente. Mudanças exclusivamente documentais não criam uma versão do jogo.

Para ensaiar sem envio: python -B Tools/publish_docs.py. Para preparar o checkout público: python -B Tools/publish_docs.py --destination Build/public-docs. O comando recusa remote diferente do destino configurado, links simbólicos, fontes/bibliotecas do jogo, arquivos ocultos e chaves privadas reconhecíveis.
