Correção R2 — CS0104 em Game/NetSession.cs

Problema e causa

O usuário executou o pacote R1 com Godot 4.7.2 .NET. A restauração do projeto concluiu, mas a compilação parou na linha 91 de Game/NetSession.cs:

error CS0104: "RandomNumberGenerator" é uma referência ambígua entre
"System.Security.Cryptography.RandomNumberGenerator" e "Godot.RandomNumberGenerator"

O arquivo importa os dois namespaces. A chamada com o nome abreviado não informa qual classe usar. A exceção posterior de Tools/Common.ps1 apenas propaga o código de saída do compilador; não é outro erro na detecção da versão do Godot.

Correção

A geração do desafio de autenticação agora usa explicitamente a classe do .NET:

// Authentication challenges need .NET's cryptographic RNG, not Godot's gameplay RNG.
string nonce = Convert.ToBase64String(
    global::System.Security.Cryptography.RandomNumberGenerator.GetBytes(32));

A quantidade permanece em 32 bytes e a codificação continua Base64. Não se usa o gerador de gameplay do Godot nem System.Random para autenticação. Os imports existentes são mantidos porque as outras funções do arquivo ainda os utilizam.

Não houve alteração de protocolo, saves, perfis, senhas, inventário, combate, mapa, assets, engine ou alvo .NET. O único arquivo de código C# alterado é Game/NetSession.cs. Os outros arquivos do patch são documentação e metadados.

Aplicar sobre o R1

Feche o Godot e as instâncias do jogo. Faça backup dos arquivos que editou. Extraia o conteúdo do ZIP de correção diretamente em:

C:\dev\ProjetoMansao-0.1.0

Mescle as pastas e substitua os arquivos. O caminho final precisa ser C:\dev\ProjetoMansao-0.1.0\Game\NetSession.cs, sem uma pasta extra de projeto.

O patch é incremental e pressupõe o R1 já aplicado. O ZIP completo R2 inclui as correções R1 e R2; não é necessário aplicar o patch R2 sobre o ZIP completo R2.

No PowerShell:

Set-Location "C:\dev\ProjetoMansao-0.1.0"
$env:GODOT_DOTNET = "C:\dev\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1

Não use -NoBuild neste teste. Não é necessário reinstalar o Godot ou o SDK para corrigir esta ambiguidade. Não exclua saves nem perfis.

Como alternativa ao ZIP, substitua apenas a linha antiga pela chamada qualificada mostrada acima e compile novamente. Não é necessário fazer as duas operações.

Validação e limites

A inspeção do pacote R1 confirmou a ocorrência reportada. Foi feita uma busca de RandomNumberGenerator em todos os arquivos C# do projeto: a chamada em NetSession é a única utilização desse tipo. Após a correção, ela está qualificada.

Foram reexecutados os validadores Python de catálogo/assets e de configuração. Também foi conferido que aplicar este patch ao R1 produz os mesmos arquivos do pacote completo R2, sem modificar os demais arquivos de código nem assets.

Não havia dotnet, Godot ou PowerShell no ambiente desta correção. Portanto, não foram executados compilação C#, testes CoreTests, importação do engine, scripts PowerShell, partida real ou exportação. Os resultados estáticos NÃO confirmam compilação nem funcionamento integrado. O build seguinte no Windows deve validar a correção e revelar eventuais outras falhas. Veja Docs/r2-validation-report.json.
