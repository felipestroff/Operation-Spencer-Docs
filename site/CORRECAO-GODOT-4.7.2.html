Correção R1 — configuração Godot 4.7.2 .NET

Problema corrigido

Tools/Common.ps1 aceitava apenas o prefixo 4.5.stable.mono, enquanto a instalação informada pelo usuário é 4.7.2.stable.mono.official.ed1daf0bf. Além disso, o projeto C# referenciava Godot.NET.Sdk/4.5.0.

O bloqueio acontecia antes da compilação: não era um erro de gameplay, driver ou ausência de C# no executável informado.

Alterações

  • SDK do projeto atualizado para Godot.NET.Sdk/4.7.2.
  • Alvo C# preservado em net8.0; global.json continua selecionando SDK .NET 8.
  • project.godot passa a registrar a linha 4.7.
  • Validador PowerShell interpreta versão numérica, canal e edição separadamente. A versão exigida vem do .csproj; a string informada pelo usuário é aceita.
  • Edições sem .NET, versões de desenvolvimento e versões diferentes do SDK continuam bloqueadas, com diagnóstico específico. Não há liberação genérica de todas as versões futuras do engine.
  • Mensagens, guia de instalação e metadados da ferramenta atualizados.
  • 22 testes de regressão PowerShell fornecidos; CI configurado para executá-los com Windows PowerShell 5.1.

Não há mudanças em gameplay, assets, dados da mansão, inventários ou saves. A versão do conteúdo continua 0.1.0-alpha; release.json identifica o patch R1.

Aplicar o patch

  1. Feche o Godot e as instâncias do jogo. Faça uma cópia da pasta do projeto.
  2. Extraia o conteúdo do ZIP de correção diretamente em C:\dev\ProjetoMansao-0.1.0, substituindo os arquivos existentes. A pasta Tools do patch deve se juntar à pasta Tools existente.
  3. Execute novamente o comando que falhou. Com GODOT_DOTNET já configurada:
Set-Location 'C:\dev\ProjetoMansao-0.1.0'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1

O ZIP completo R1 é alternativa ao patch. Não aplique ambos como etapas distintas. Não aponte para Godot 4.5 após atualizar o projeto para SDK 4.7.2.

Para informar explicitamente a instalação, ajuste o caminho real:

$env:GODOT_DOTNET = 'C:\Ferramentas\Godot\Godot_v4.7.2-stable_mono_win64_console.exe'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1

Preserve a pasta GodotSharp que acompanha a edição .NET. Exporte com templates .NET 4.7.2, não com templates 4.5. A primeira restauração de dependências pode precisar de acesso ao NuGet. Não use -NoBuild na primeira execução após o patch.

Testar somente o validador

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Test-Toolchain.ps1

O resultado esperado é 22 tests; 0 failures. Esse é um teste do validador, não uma compilação do jogo nem uma validação de multiplayer.

Evidências e limites

Veja toolchain-r1-report.json para as verificações realizadas nesta correção. O relatório estático pode ser reproduzido com python Tools/validate_toolchain.py. A checagem estática em Python reproduz os casos de versão e verifica a coerência entre .csproj, project.godot e release.json. Ela não executa PowerShell. Os testes PowerShell foram escritos, mas não executados: não há PowerShell, Godot ou SDK .NET no ambiente de geração. A obtenção de ferramentas também falhou por resolução de DNS. Build C#, importação Godot, exportação e multiplayer continuam não homologados. Não há executáveis prontos no pacote.
