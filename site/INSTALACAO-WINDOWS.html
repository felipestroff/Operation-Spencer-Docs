Instalação, compilação e execução no Windows

Para execução pelo Codex, consulte Godot/.NET no Codex. Tools/Setup-Codex.ps1 persiste o caminho validado do engine; Tools/Test.ps1 executa os gates automáticos com logs e relatório por execução. Build/26 CoreTests/importação e smoke ENet foram aprovados localmente em 13/10/2026 após corrigir o bot. Os limites estão no guia. As notas da entrega abaixo são históricas.

Correção R1 do bloqueio de versão

O projeto agora exige Godot 4.7.2 stable .NET, com Godot.NET.Sdk/4.7.2 e alvo net8.0. A validação PowerShell lê a versão do SDK diretamente de OperationSpencer.csproj; não mantém outro número fixo no script. A saída 4.7.2.stable.mono.official.ed1daf0bf é reconhecida pelo novo validador. Feche o editor e aplique todos os arquivos do patch sobre a raiz do projeto. Não altere apenas Common.ps1. Veja CORRECAO-GODOT-4.7.2.md.

Estado da entrega

A automação atual distribui fontes, tags e notas, sem binários. Existem builds e importações locais registrados por revisão em Testes e limitações. Os comandos abaixo permitem reexecutá-los; preserve a saída caso uma etapa falhe. Não pule testes para considerar a versão aprovada.

Pré-requisitos fixados

Dependência Seleção
Godot 4.7.2 stable .NET, Windows x64; não a edição sem C#
.NET SDK 8 x64, não somente Runtime
Templates de exportação 4.7.2 stable .NET, apenas para exportar
Python 3.10+ com Tools/requirements-art.txt para validadores e geradores; não é dependência do runtime do jogo
GPU Compatível com o renderer Compatibility do Godot; desempenho não aferido

Engine e templates: https://godotengine.org/download/archive/4.7.2-stable/ SDK: https://dotnet.microsoft.com/en-us/download/dotnet/8.0 Documentação C#: https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/c_sharp_basics.html

A versão foi fixada para reduzir variação da API, não apresentada como a versão mais recente do Godot. global.json aceita atualizações de feature band do SDK 8. O pacote não traz SDK, engine, templates ou fontes tipográficas.

Extraia a pasta inteira do Godot, preservando GodotSharp junto dos executáveis. Extraia também o projeto; não execute arquivos dentro do ZIP. Evite pasta protegida ou sincronização concorrente por nuvem durante a primeira compilação.

Verificação de instalação

Abra um PowerShell novo e execute:

dotnet --list-sdks
& "C:\Ferramentas\Godot\Godot_v4.7.2-stable_mono_win64_console.exe" --version

O primeiro comando deve listar um SDK 8.x; o segundo deve identificar 4.7.2.stable.mono. Feche e abra o terminal depois de instalar o SDK.

Compilar e abrir o menu

Entre na pasta que contém project.godot, OperationSpencer.csproj e OperationSpencer.sln.

$env:GODOT_DOTNET = "C:\Ferramentas\Godot\Godot_v4.7.2-stable_mono_win64_console.exe"
python -m pip install -r Tools/requirements-art.txt
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1

Esse comando tenta, em sequência: build C#, testes de núcleo/navegação, importação dos GLBs/áudios/texturas e abertura do jogo. INICIAR.cmd é um atalho para o mesmo processo, desde que GODOT_DOTNET tenha sido definida no ambiente que o inicia. Para evitar depender de variável, use diretamente -Godot "caminho completo".

Para abrir pelo editor, importe project.godot, espere a importação dos recursos, compile o C# e use F5. O nível é construído em execução por RoomView a partir de Data/scenario.json; o editor não abrirá 34 cenas decoradas individualmente. Os GLBs individuais podem ser inspecionados no importador/editor.

Partidas separadas para testes

# Campanha nova de solo; usar -New substitui o progresso dessa campanha.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1 -Mode Solo -Profile teste-jill -Character jill -Campaign teste-solo -New

# Anfitrião-jogador; mantém uma campanha própria.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1 -Mode Host -Profile anfitriao -Character jill -Campaign amigos

# Cliente local. Outro computador deve usar o IP do anfitrião.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Run.ps1 -Mode Join -Profile amigo-chris -Character chris -Address 127.0.0.1 -NoBuild

Use -NoBuild apenas depois de uma compilação/importação aprovada, sem editar fontes desde então. IDs válidos: jill, chris, wesker, rebecca, barry.

Exportar Windows e Linux

No editor, instale os templates .NET da mesma versão. Depois:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Build.ps1 -Godot $env:GODOT_DOTNET -Export All

Saídas previstas: Build/Windows/ e Build/Linux/. Distribua a pasta inteira de cada exportação: executável, PCK e diretórios/bibliotecas .NET gerados. Não copie apenas o .exe. Os presets não têm assinatura de código nem ícone de executável customizado. O preset Linux exporta recursos completos; o servidor é selecionado por --headless -- --server, não por remoção prévia das texturas. As exportações ainda precisam ser executadas e verificadas em máquinas-alvo.

Diagnóstico

Sintoma Verificação
Scripts desabilitados Use o comando com powershell.exe -ExecutionPolicy Bypass -File; a mudança é só do processo.
SDK ausente Instale SDK 8 x64, não Runtime; confirme dotnet --list-sdks.
Engine incompatível Use 4.7.2 stable .NET e preserve a pasta GodotSharp.
Falha NuGet Verifique acesso à internet, proxy e mensagens de restauração.
Erro de C# Registre arquivo, linha e mensagem; consulte os resultados por revisão em TESTES-E-LIMITACOES.md.
Modelo não aparece Confira a aba de importação, mensagens do GLB e reimporte antes de jogar.
Tela preta Verifique erro de boot, renderer Compatibility e log, antes de alterar câmeras.
Exportação sem solução OperationSpencer.sln deve permanecer na raiz junto do csproj.
Jogadores não conectam Consulte o guia multiplayer: versão, IP, UDP, firewall, vagas e personagens.

O console imprime USER_DATA com o diretório efetivo de dados. Nele ficam profiles/, campaigns/ e settings.json. Faça backup antes de apagar ou editar saves. Perfis contêm uma chave privada de identidade local: não a publique em logs.
